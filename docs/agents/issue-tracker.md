# Issue tracker: none

This repo does not track issues. Work is defined by the implementation specs in `specs/` (see the execution plan in `AGENTS.md`).

## When a skill says "publish to the issue tracker"

Don't create issues anywhere. Present the output in the conversation and ask the user where, if anywhere, it should be saved.

## When a skill says "fetch the relevant ticket"

There are no tickets. Use the assigned spec in `specs/` as the source of requirements, or ask the user.
